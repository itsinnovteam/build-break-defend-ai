The agent loop: think, act, observe, repeat

One tool call in a loop - with a hard stop

From one tool call to an agent

Section 1 was a single round trip. An agent just puts that round trip in a loop: think → call a tool → read the result → think again, and keep going until it can answer or it hits a limit. Each turn the model sees everything so far and decides the next step - the steps are not fixed in advance.

Analogy - a detective. A detective does not know the whole case up front. They follow one lead, see what it turns up, and let that decide the next lead. They stop when the case is solved - or when they run out of time. An agent loops the same way, and the time limit matters just as much as the cleverness.
SOC: read the alert → the IP looks odd → check its reputation → malicious → write a case note → done. DevOps: read the alarm → check pod status → still failing → read recent deploys → summarise. The loop found its own path through the tools.

The loop must be able to stop

A loop that cannot stop is a danger all by itself - a bug or an attacker could spin it forever, burning the machine and calling tools again and again. Lab 5 sets two hard limits in config.py: MAX_STEPS = 8 and MAX_TOOL_CALLS = 10. When either is hit, the loop stops and returns what it has. Limits are a security control, not just tidiness.
