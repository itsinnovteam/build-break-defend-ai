AI Bootcamp - Module 5 - Section 1 - Tool and function calling

Tool calling: the model proposes, your code disposes

The one mechanism every agent is built on

What "tool calling" really is

A chat model can only produce text. By itself it cannot look up an IP, read a ticket, or block anything. Tool calling is the trick that lets it act: we hand the model a menu of tools, and when it wants one it returns a small request - the tool name and the arguments - as structured data. It never runs anything itself.

Analogy - the order ticket. A diner does not walk into the kitchen and cook. They write an order ticket ("one omelette, no onions") and hand it to the pass. The kitchen decides whether and how to cook it. The model is the diner writing tickets; your code is the kitchen. The model proposes; your code disposes.

SOC: "Is 198.51.100.20 malicious?" → the model asks for lookup_ip_reputation. DevOps: "Is the payments pod healthy?" → it asks for get_pod_status. Helpdesk: "Who owns laptop-20?" → it asks for get_asset_owner. Same mechanism, different menu.

Watch one round trip

Pick a question. You play "your code" - the model will hand you a ticket, and you decide to run it. This is exactly what python tool_demo.py prints in the lab.

Why this matters for security

Because the model only ever returns a request, there is exactly one place where anything actually happens: the line in your code that decides to run the tool. That single checkpoint is where every defence in Section 5 and Lab 5 lives. Hold onto that idea - it is the whole module in one sentence.
