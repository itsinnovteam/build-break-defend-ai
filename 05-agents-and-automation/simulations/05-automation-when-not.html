AI Bootcamp - Module 5 - Section 4 - When not to use agents

When NOT to use an agent

The cheapest, safest agent is often a plain script

The most secure agent is often no agent

Agents are powerful because they decide their own steps - but that same freedom is the attack surface this whole module is about. Before building one, ask: do the steps actually change from run to run? If the recipe is fixed, a plain script is cheaper, faster, fully repeatable, and has no prompt-injection risk at all.

Analogy - don't hire a detective to read a thermometer. A detective is worth it for an open case with unknown leads. For "what's the temperature?", you just read the dial. Paying for improvisation when the steps are known is wasted money - and extra risk.
SOC: "block every IP on this known-bad list" is a fixed loop - a script. "Investigate this odd login and decide what matters" is open-ended - maybe an agent. DevOps: "restart the service if health check fails" is a script; "figure out why last night's deploy is flaky" may need an agent.

Script or agent? Decide a few tasks

The plain triage, for comparison

When the triage recipe is fixed, the lab's plain script does it with zero model calls - deterministic, same answer every run, nothing to hijack:

$ python plain_vs_agent.py

  alert: A-1007
  verdict: malicious
  recommend: block IP + reset password
  model_calls: 0
  tool_calls: 3

Rule of thumb from the lab: reach for a script or a RAG lookup (Modules 3 and 4) first. Use an agent only when the task truly needs to decide its own steps - then secure it with Section 5.
