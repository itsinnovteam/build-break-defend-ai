This is the no-terminal walkthrough.      tool: lookup_ip_reputation(ip)

2. The model did NOT run anything. It asked us to call a tool:

     result: {"ip": "198.51.100.20", "risk_score": 92, "verdict": "malicious"}

That is the whole mechanism. The model proposes; your code disposes. Section 5.5
(and Lab 5) is about making step 3 safe.

Phase 4 - When not to use an agent

The same triage as a plain script: zero model calls, deterministic, nothing to hijack.

$ python plain_vs_agent.py
PLAIN SCRIPT (no agent):
  alert: A-1007
  verdict: malicious
  recommend: block IP + reset password
  model_calls: 0
  tool_calls: 3
  deterministic: True

  Same result every run. No model, so no prompt-injection risk. Easy to test.

WHEN A PLAIN SCRIPT IS THE RIGHT CHOICE
  - The steps are fixed and known in advance (this triage recipe).
  - The task runs often, or must be cheap, fast and 100% repeatable.
  - A wrong action would be costly, and you want zero run-time surprises.
  - You cannot afford the attack surface an agent adds.

WHEN AN AGENT EARNS ITS RISK
  - The steps are NOT known ahead of time and depend on what each tool returns.
  - A human would otherwise improvise across many tools (open-ended investigation).
  - The flexibility is worth the extra cost, latency and the security work in Lab 5.

Rule of thumb: reach for a script or a RAG lookup first (Modules 3 and 4). Use an
agent only when the task really needs to decide its own steps - then secure it.
[exit 0]

THE FOUR DEFENCES - each stops a different bad tool call
  1 Least privilege  disable_account(svc-backup) -> blocked: tool 'disable_account' is not allowed for this task (least privilege)
  2 Human approval   block_ip(198.51.100.20) -> denied: a human did not approve this write action
  3 Argument check   disable_account(svc-backup) -> blocked: argument check failed: 'svc-backup' is a critical account and must not be disabled by the agent
  4 Argument check   send_email(x@mail.external-review.example) -> blocked: argument check failed: recipient 'x@mail.external-review.example' is not internal (allowed: example.com)
  5 Data not orders  every tool result is wrapped in <observation> and never executed
