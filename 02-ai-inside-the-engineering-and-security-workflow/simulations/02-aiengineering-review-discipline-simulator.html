Simulation 2 - The Review Discipline

Be the reviewer. Find what the AI got wrong before it reaches production, and match review effort to risk.

Part A - Review the AI's code before it runs

Think of it like... A building inspector. The contractor (AI) works fast, but nobody moves in until the inspector signs. If the building falls, "the contractor built it" is not a defence - the inspector signed.

The requirement given to the AI:

Delete .log files older than 30 days, only inside D:\logs\app. Dry-run by default (print, don't delete). Report any errors.
How to play: Click every line that breaks the requirement or is unsafe. There are 6. Then press Submit review.

Part B - How deep should the review be?

Think of it like... Airport security. A carry-on bag gets an X-ray; a suspicious bag gets opened by hand; cargo for a VIP flight gets a second team. Effort follows risk.
How to play: Pick the review level for each AI output.
Light = read it and sanity-check. Standard = read every line, run it, test edge cases. Deep = Standard + security scan + a second human reviewer before production.
